# 你今次嘅工作：生意體檢

創辦人已經成頁確認公司概覽。請按公司紀錄做一次生意體檢：搵出生意最弱嘅三個環節、創辦人可能未想到嘅事、目前唔建議做嘅事。同一個資料夾：

- `confirmed-page.md`：創辦人確認咗嘅公司概覽（只可以讀）。
- `ledger.json`：公司紀錄嘅假設清單（`id`、內容、證據級 `grade`、最便宜測試）、里程碑（次序 `order`、是否已確認 `confirmed`、進度 `state`）、本季目標（`quarterGoal`）同下一個對外動作（只可以讀）。
- `feedback.md`：創辦人上次對生意體檢結果卡嘅意見（有用／沒有用／要修改＋一句）。
- `previous.json`：上一次生意體檢結果（第一次就冇）。

## 規矩（一定要守）

1. 只可以讀寫呢個資料夾；只寫 `out/checkup.json`。唔好擬問題包，唔好寫其他產出。
2. **只按紀錄講**：弱位要指向 `ledger.json` 入面一條假設（`assumptionId` 寫佢嘅 `id`）；唔好寫紀錄冇嘅人名、數字、日期或者承諾。證據級由外殼按紀錄填，你唔使寫、亦唔可以改。
3. 每個弱位寫：點解弱（一兩句，講紀錄入面缺咗乜證據）、最便宜嘅測試（一件公司以外、本週做得到、有結果嘅事）、停止條件（測試結果點樣就要改做法）。
4. **唔可以同已確認嘅計劃矛盾**（所有 AI 建議都守）：先讀已確認值——`confirmed-page.md`、本季目標、已確認里程碑嘅次序同進度（`confirmed`、`order`、`state`）、下一個對外動作。最便宜嘅測試同所有建議唔可以跳過或者搶先已確認嘅次序同下一個對外動作（例如次序寫明先見伙伴、之後先揀試行客戶，就唔好建議本週自己揀客戶）；要到後面某一站先做得到，就寫明「到第幾站時可以做」。發現已確認值之間有矛盾（例如兩處寫法唔同），唔好自行判斷用邊個，寫入 `unseen`，講明要創辦人確認以邊個為準。
5. **照顧創辦人上次嘅意見**：「沒有用」嗰類唔好再寫；「要修改」照佢講嘅改；「有用」嘅方向可以保留。
6. **紀錄冇寫唔等於冇**：你只見到公司概覽同公司紀錄，見唔到創辦人全部文件；紀錄冇講嘅事唔可以寫成「冇」「未有」「未做」，要寫「公司紀錄未有記錄」，並建議創辦人補上（走查揭出：曾經將紀錄未有嘅事寫成「沒有」）。
7. 體檢只係 AI 解讀，唔係證據；唔好話任何假設已經證實。
8. 畫面文字用書面語白話；唔可以有內部用語（例如 G 編號、假設編號、檔名、run、ledger）。外殼會檢查。

## 要交

`out/checkup.json`（只可以係有效 JSON）：

```json
{
  "summary": "一句：今次體檢最要緊嘅發現",
  "weak": [
    { "title": "最弱環節（一句）", "assumptionId": "H2", "why": "點解弱", "cheapestTest": "最便宜嘅測試", "stop": "停止條件" }
  ],
  "unseen": [ { "text": "創辦人可能未想到嘅一件事" } ],
  "notNow": [ { "text": "目前唔建議做嘅事", "why": "點解" } ]
}
```

`weak` 最多三項，按最弱排先；`unseen`、`notNow` 各最多三項。做完就停。
